# M2: the processing pipeline. Guide for contributors

M2 turns `bibers` into a working program: `.bcf` + data → `.bbl`, byte-identical to biber 2.22 (with the deliberate differences of `docs/compat.md`). Read `docs/PLAN.md` (§4–§6) and `docs/compat.md` first.

## Architecture (already in place)

- `bibers-core::model`: the in-memory state, mirroring biber's `Biber::Section`, `Biber::Entry`, `Biber::Entry::Names`/`Name` and `Biber::DataList`.
  - Typed where biber's shape is fixed.
  - `PerlData` (JSON-shaped) slots hold state whose shape is still being ported.
  - Name lists live in a per-section arena (`NameListId`) and are shared by copying the id (biber shares `Names` objects; BB-026).
- `bibers-core::pipeline`: a function-by-function port of `Biber::prepare` and `Biber::process_lists`.
  - Phases are `fn(&mut Ctx, &mut SectionState[, list])`, listed in `SECTION_PHASES`/`LIST_PHASES` under biber's method names.
  - `Ctx` gives access to the options (`ctx.cfg`, incl. per-entry options), the data model (`ctx.dm`), the parsed `.bcf` (`ctx.doc`), the logger and the environment.
- `bibers-core::output::bbl`: the `.bbl` writer.
- `bibers::run`: `setup` (CLI, config, `.bcf`), then `process` (`prepare`, `render`, write).

## Method: phase-level differential testing

`tools/oracle/probes/pipeline/BiberPhaseDump.pm` makes the source-built biber (oracle O3) dump its complete section state after every phase, plus an `init` dump before `fetch_data`. The dumps are canonical JSON, cached per corpus case under `target/phase-dumps/` by `bibers_testkit::phase`. `bibers_core::model::dump` loads such a state into the Rust model and dumps it back in the same format (verified lossless on all 3,596 dumps of the `tdata` and `biblatex-examples` suites).

To test a phase:

```rust
// crates/bibers/tests/phase_<area>.rs
mod common;

#[test]
fn sort_list_matches_biber() {
    common::phase::assert_phase("sort_list", &["tdata/sort-order", "styles/authoryear"]);
}
```

`assert_phase` loads biber's state from just **before** each occurrence of the phase (every section, every data list), runs the Rust phase, and diffs against biber's state just **after** it, path by path. It reproduces what `process_lists` does around per-list phases: `init_list` before `process_entries_pre`, and `filter_list` before `generate_sortdataschema`. Tests skip when O3 isn't built (CI). `assert_phase_ignoring` takes extra ignored paths (`*` matches one component), for fields another package is still porting.

Useful:
- `cargo xtask list`.
- `common::phase::cases_with_prefix(&["tdata/"])`.
- `tools/oracle/probes/pipeline/run.sh <dir> <biber args>` to look at dumps by hand.
- `target/phase-dumps/<case>/dumps/*.json`.

The end-to-end check is `cargo xtask corpus` (whole `.bbl` vs biber's golden) and the `tests/corpus/passing.txt` ratchet.

## Conventions

- **Port faithfully, function by function.** Cite `Biber.pm:<line>` (vendor/biber @ v2.22) in doc comments. Keep biber's iteration orders. Where biber iterates a Perl hash and the result is order-dependent, choose a deterministic order and report it (it needs a `docs/compat.md` entry).
- **Perl-isms** go through `perl-compat`: `perl_truthy` (`"0"` is false!), `looks_like_number`, `lc`/`uc`/`fc`, `nfd`/`nfc` (Unicode 16), the `gcstring` grapheme functions (Unicode 8, as `Unicode::GCString`), `\X` (Unicode 16), `PerlRegex` for user-supplied regexes, `Isbn`, `uri_as_string`, roman numerals. Don't use Rust's `to_lowercase` or `unicode-segmentation` in their place: the tables differ.
- **Collation** goes through `ucollate` (`CollateOptions::biber_sort`, `biber_sortinit`). **BibTeX parsing** goes through `btparse`, and **LaTeX decoding/encoding** through `latex-recode`.
- **Reproduced biber bugs** go behind `bibers_core::quirks::Quirk` variants (name them after the bug, cite the `BB-NNN` id). The default reproduces biber.
- **Model changes:** you may type-ify state you own, but `model::dump` must keep producing exactly biber's JSON. Keep changes to shared model types small and additive, because other packages work in parallel. Performance work (typed hot state, interning) is M5; correctness first.
- **Don't edit** `docs/biber-bugs.md`, `docs/compat.md` or `docs/PLAN.md` (packages run concurrently). Report bugs and intended differences in your final report.
- Before finishing:
  - `cargo fmt --all`;
  - `cargo clippy --workspace --all-targets -- -D warnings`;
  - `cargo test --workspace`;
  - your phase tests, run locally with O3.

## Work packages

| Package | Owns | Phases (dump names) / test |
|---|---|---|
| fetch | `pipeline/fetch.rs` (+ submodules) | `fetch_data`: data source location and globbing; bibtex reading via `btparse` (biber's two-pass parse + `latex_decode`, reproduced in memory); `create_entry` field handlers (names via `parsename`, dates, ranges, lists, xsv, verbatim/URI, annotations, the `options` field → per-entry options); `get_dependents`; preambles. Calls `sourcemap::apply_maps`. |
| sourcemap | `pipeline/sourcemap.rs` | The map engine, tested inside `fetch_data` (map-heavy cases) plus its own probes. |
| resolve | `pipeline/resolve.rs` | `process_citekey_aliases`, `instantiate_dynamic`, `resolve_alias_refs`, `resolve_xdata`, `cite_setmembers`, `preprocess_sets`, `calculate_interentry`, `process_interentry`, `validate_datamodel`, `postprocess_sets` |
| entries | `pipeline/entries.rs`, `lists::generate_contextdata` | `process_entries_static`, `process_entries_pre`, `process_visible_names`, `process_entries_post` (except labelalpha), `process_entries_final`, `generate_contextdata` |
| labelalpha | `pipeline/labelalpha.rs` | labelalpha/extraalpha within `process_entries_post` |
| uniqueness | `pipeline/uniqueness.rs` | `uniqueness` |
| sort | `pipeline/sort.rs`, `lists::filter_list` | `generate_sortdataschema`, `generate_sortinfo`, `sort_list`, list filters |
| output | `output/bbl.rs` | `.bbl` rendering, tested by rendering biber's final section states (the `process_lists` dumps) and comparing with the corpus goldens |
