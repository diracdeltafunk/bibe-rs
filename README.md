# bibe-rs

A fast, behaviour-compatible Rust port of [biber](https://github.com/plk/biber), the biblatex backend. The binary is called **`bibers`**. It aims to produce byte-identical `.bbl` output to biber 2.22, at least 50× faster.

**Status: 0.1.0, a preview release.** `bibers` produces output byte-identical to biber 2.22, apart from the documented deliberate differences in [docs/compat.md](docs/compat.md). That holds on all 776 test-corpus cases (`.bbl`, tool mode and bibtex output, biblatexml, validation, remote sources, every Perl encoding), on all 964 TeX Live `.bib` files across 8 styles, on 163 real biblatex documents, and across about 100,000 random differential tests. It is about 100× faster than biber on large bibliographies (see below). It implements biber 2.22, so it works with biblatex 3.22 (control file format 3.11).

As a preview, it hasn't yet met the variety of real documents biber has. If bibers and biber disagree on one of yours, please [open an issue](https://github.com/diracdeltafunk/bibe-rs/issues/new/choose) with the `.bcf` and `.bib`. That is the most useful thing you can do.

## Install

bibers is a single self-contained executable. It needs no Perl and no data files, and it can be installed next to biber: it does not replace or change your TeX distribution's `biber`.

### Prebuilt binaries

Each [release](https://github.com/diracdeltafunk/bibe-rs/releases) has an archive per platform, holding `bibers` (`bibers.exe` on Windows), the licence files (`LICENSE`, `NOTICE.md`, `LICENSES/`, `THIRD-PARTY-LICENSES.md`), `README.md` and `docs/compat.md`:

| Platform | Archive |
|---|---|
| macOS (Apple silicon and Intel) | `bibers-<version>-universal-apple-darwin.tar.gz` |
| Linux x86_64 (static, any distribution) | `bibers-<version>-x86_64-unknown-linux-musl.tar.gz` |
| Linux aarch64 (static, any distribution) | `bibers-<version>-aarch64-unknown-linux-musl.tar.gz` |
| Windows x86_64 | `bibers-<version>-x86_64-pc-windows-msvc.zip` |

1. Download the archive for your platform and `SHA256SUMS`, and check the archive:
   `shasum -a 256 -c SHA256SUMS --ignore-missing` (on Windows: `Get-FileHash bibers-….zip` and compare).
2. Unpack it and put `bibers` in a directory on your `PATH`, for example `~/.local/bin` or `/usr/local/bin` (on Windows, any folder listed in the `Path` environment variable).
3. Check: `bibers --version` prints `bibers version: <version> (biber 2.22 compatible)`.

The binaries are not code-signed. On macOS, if Gatekeeper refuses to run a copy downloaded with a browser, remove the quarantine flag: `xattr -d com.apple.quarantine bibers`. On Windows, SmartScreen may warn the first time you run `bibers.exe`; choose "More info" and then "Run anyway".

### From source

With [Rust](https://rustup.rs) 1.88 or later and a C compiler (for the bundled PCRE2 and for `ring`):

```sh
git clone https://github.com/diracdeltafunk/bibe-rs
cd bibe-rs
cargo install --locked --path crates/bibers
```

This installs `bibers` into `~/.cargo/bin`.

## Using bibers instead of biber

bibers takes biber's command line and `biber.conf`, reads the same `.bcf` and writes the same `.bbl` and `.blg`, so anything that runs `biber` can run `bibers` instead. Your documents don't change: keep `backend=biber` in biblatex. bibers implements biber 2.22, which goes with biblatex 3.22 (control file format 3.11); like biber 2.22, it stops with an error on a `.bcf` from a biblatex that needs a different biber.

### latexmk

In `.latexmkrc` in the document's directory, or in `~/.latexmkrc` for all documents:

```perl
$biber = 'bibers %O %S';
```

latexmk then runs bibers whenever it would run biber, and reruns it as usual (it finds the data files from the `.bcf` and `.blg`, which bibers writes in biber's format).

### arara

arara's `biber` rule always runs `biber`. Add a `bibers` rule (modelled on arara's own `biber` rule; it has not yet been tested with arara itself, so reports are welcome): save this as `bibers.yaml` in a rules directory, for example `rules/` next to the document, and list that directory in `araraconfig.yaml` (`paths: ['./rules']`):

```yaml
!config
identifier: bibers
name: bibers
authors:
- bibe-rs
commands:
- name: bibers (biber-compatible)
  command: >
    @{
        return getCommand('bibers', options, getBasename(reference.getName()));
    }
arguments:
- identifier: options
  flag: >
    @{
        if (isList(parameters.options)) {
            return parameters.options;
        }
        else {
            throw new Exception('The provided options must be a list.');
        }
    }
```

Then use `% arara: bibers` where you had `% arara: biber`.

### TeXstudio

*Options → Configure TeXstudio → Commands*: set **Biber** to `bibers %`. The *Build* page's *Default Bibliography Tool* stays *Biber*.

### TeXShop

*TeXShop → Settings → Engine*: set **BibTeX Engine** to `bibers`. *Typeset → BibTeX* (⌘⇧B) then runs bibers. If you typeset with TeXShop's latexmk engines instead, use the latexmk setting above.

### VS Code (LaTeX Workshop)

The default recipe runs latexmk, so the latexmk setting above is enough. For recipes that call biber directly, define a `bibers` tool in `settings.json` and use it in your recipes, for example:

```json
"latex-workshop.latex.tools": [
  {
    "name": "pdflatex",
    "command": "pdflatex",
    "args": ["-synctex=1", "-interaction=nonstopmode", "-file-line-error", "%DOC%"]
  },
  { "name": "bibers", "command": "bibers", "args": ["%DOCFILE%"] }
],
"latex-workshop.latex.recipes": [
  { "name": "pdflatex → bibers → pdflatex × 2", "tools": ["pdflatex", "bibers", "pdflatex", "pdflatex"] }
]
```

(Setting `latex-workshop.latex.tools` replaces the built-in list, so include every tool your recipes use.)

### Servers and CI (self-hosted Overleaf, Docker images)

Put the static Linux binary in the image (for example in `/usr/local/bin`) and set latexmk's `$biber` as above, in the image's global latexmkrc or in a `latexmkrc` file in the project. On hosted services you can't install programs on (such as overleaf.com), bibers can't be used.

### Replacing `biber` itself

To make every tool use bibers without configuring each one, put a `biber` that runs bibers ahead of your TeX distribution's on the `PATH`:

```sh
mkdir -p ~/.local/bin
ln -s "$(command -v bibers)" ~/.local/bin/biber   # ~/.local/bin must come before TeX's bin directory in PATH
biber --version                                    # bibers version: … (biber 2.22 compatible)
```

On Windows, copy `bibers.exe` to `biber.exe` in a folder that comes before TeX Live's or MiKTeX's `bin` folder in `Path`. Prefer this to overwriting the distribution's own `biber`: the distribution's updater (`tlmgr`, the MiKTeX console) may restore it, and removing the link brings biber back. A shell alias (`alias biber=bibers`) only affects commands you type in that shell, not editors or latexmk.

Before replacing biber, check [docs/compat.md](docs/compat.md) for the differences that might matter to you. The main ones:

- **Version and banner:** `biber --version` and the log banner say `bibers` (`This is bibers <version> (biber 2.22 compatible)`, DC-040), so scripts that parse biber's version string see a different one.
- **Dropped or unsupported:** the deprecated `bblxml` and `dot` output formats and `bibjson` (DC-020–022), `--validate-bblxml` (DC-033), and the `UTF-7`, `gsm0338` and `MIME-*` encodings (DC-034) give an error.
- **Perl in sourcemaps:** Perl code in sourcemap replacement strings is not executed (DC-023), and user regexes run on PCRE2 behind a Perl-syntax layer, so a few Perl-only constructs are rejected with an error (DC-036).
- **Fixes:** inputs that crash, hang or lose data in biber give an error or the intended result in bibers, and output that depends on Perl hash order in biber is deterministic (§1 of compat.md). Everything else, including biber's output-affecting bugs, is reproduced by default (§2).
- **Messages:** log lines tagged with source locations, `--debug`/`--trace` output and a few error texts differ (§5); `--tool-config` prints the built-in `biber-tool.conf` rather than its path (DC-055).
