# Ported biber tests (`t/*.t`)

biber 2.22 ships 51 test files with **1275** TAP tests. They drive biber in-process (`Biber->new`, `setoption`/`setblxoption`, `parse_ctrlfile`, `prepare`) and then inspect objects or compare `.bbl` entry strings. This directory and `tests/corpus/ported/` turn them into black-box checks for bibers (docs/PLAN.md §6.2 item 2).

168 corpus cases (`tests/corpus/ported/<tfile>-<n>`, tags `suite:ported`, `t:<tfile>`; 9 of them are tool/bibtex/biblatexml output and also carry `deferred:m4`). Fidelity-check failures: **0**.

## How it works

Everything is regenerated by the scripts in `tools/port-tests/` (outputs in `tools/port-tests/out/`, gitignored):

1. **Trace** (`trace.sh` + `BiberTrace.pm`): runs each `t/*.t` under oracle O3 with an instrumentation module that wraps every `Biber::*` sub and the Test::More/Test::Differences assertions. Calls made by the `.t` itself (not biber-internal ones) are logged with arguments and return values, every assertion with got/expected and its TAP numbers, and after each `prepare()` the complete in-process `.bbl` is dumped. All 1275 tests still pass under the instrumentation.
2. **Configurations** (`traceconf.py`): replays the log as a state machine. Each `prepare()` snapshots the configuration: `Biber->new` arguments, `.bcf`, `setoption`/`setblxoption` calls, datalist template changes, key-set changes. Assertions belong to the latest `prepare()`.
3. **Cases** (`gen.py`): one corpus case per distinct configuration that has assertions. `setoption` becomes a CLI flag (`--configfile` for structured options); `setblxoption` and `nosort`/`noinit`/`nolabel`/`nolabelwidthcount` become edits of a copy of the `.bcf` (`<bcf:options component="biblatex">` blocks, template elements); `set_sortingtemplatename` changes the datalist (or the global `sortingtemplatename`, which renames the list); `set_allkeys` becomes `\nocite{*}`. `--sortdebug` is added when sort keys are asserted. State the tests set outside traced subs is handled by small per-file overrides (`OVERRIDES`, `SUBPROCESS_CASES`). Goldens: `cargo xtask golden ported/` (O1; O3 reproduces them, `golden --check --oracle o3`).
4. **Fidelity check** (`check.py`): for every assertion it finds the accessor the test checked and verifies the expected value from the `.t` against the golden of the matching case: entry text (`get_output_entry`) in the `.bbl` section/list; key order (`get_keys`) against the datalist; `get_sortdata_for_key` and `sortlabelalpha` against the `--sortdebug` lines; `get_unsummary`/`get_uniquelist` against `un=`/`ul=` in the `\name` blocks; `get_entryfield`/`get_extra*data`/`get_labelalphadata` and `$entry->get_field` against `\field`/`\strng`/`\true`/`\list`/`\verb`/ranges; datamodel warnings and error texts against `expected/messages.txt`; full `$outvar` outputs (encoding.t, tool modes) against the whole file. Results: `out/fidelity.json`.
5. **Translation check** (`replaycheck.py` + `replay.pl`): replays each case's configuration in a *fresh* in-process O3 biber (same calls as the `.t`, without the earlier `prepare()`s) and compares the whole `.bbl` with the CLI golden: 154 identical, 1 differ, 3 replay crashes (of 158 `.bbl` cases).
   The one difference (sort-order-16) is a stale citecount from the keys the test deleted; the crashes (sort-uc-3..5) are in-process `output()` dying when no list uses the global sorting template, which a CLI run cannot reach.
6. **Unit vectors** (`vectors.py`): assertions about internals that no output shows.
7. **This README** (`report.py`).

Regenerate: `tools/port-tests/trace.sh && cd tools/port-tests && python3 gen.py && (cd ../.. && cargo xtask golden ported/) && python3 check.py && python3 replaycheck.py && python3 vectors.py && python3 report.py`. `dumpdiff.py <case>` diffs a case against the in-process dump.

## Findings

- **BB-114** (new, docs/biber-bugs.md): in tool mode the biblatexml writer outputs entries in citekey order and ignores the `tool` sorting template that the bibtex writer applies (tool-bltxml.t asserts the sorted list, which never reaches the file).
- `$MAPUNIQ` (BB-113) makes basic-misc-2..4 nondeterministic; the oracle runs differ only in the `loopkey:<x>:<random>` keys.
- Test-suite quirks (not biber bugs): `set_sortingtemplate()` in sort-case.t/sort-uc.t has no effect; labelalpha.t asks for key `l1` instead of `L1` three times (vacuous); basic-misc.t:604-605 assert state left over from an earlier `prepare()`; crossrefs.t and annotations.t set package globals directly; bibtex-output.t sets the `tool` option outside tool mode; the in-process tests reuse the output object, so its entries accumulate across `prepare()` calls.
